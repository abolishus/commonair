# Deviations from upstream shadcn/ui

The upstream reference is a scratch project made with the pinned CLI and the preset:
`bunx shadcn@4.21.1 init -t vite -b base -p b1ZhhFNpx`, `iconLibrary: hugeicons`, then every
component in `scripts/shadcn-add.ts` `COMPONENTS` added. `bun scripts/shadcn-add.ts --snapshot`
regenerates it into `upstream/` (aliases mapped to `@commonair/ui/…`, each file normalized with
`normalizeComponentSource` and formatted; stored as `.txt` so lint and typecheck skip it; test data,
never exported).

Every file in `src/components/` and `src/hooks/` either equals its upstream file byte for byte or
has a row below (`tests/deviations.test.ts`). After `bun scripts/shadcn-add.ts <x> --overwrite`,
re-apply the rows for `<x>`.

**Right-to-left (N2-rtl, ADR 0029 decision 5).** Every component with a physical-direction class
carries upstream's own RTL transform (shadcn `applyRtlMapping`, what `components.json` `rtl: true`
does on `add`): `ml-`/`pl-`/`left-`/`border-l`/`rounded-l`/`text-left` become `ms-`/`ps-`/`start-`/
`border-s`/`rounded-s`/`text-start`, `translate-x` gains an `rtl:` counterpart, menu sub-content
`side="right"` is `"inline-end"`, and directional icons get `rtl:rotate-180` (`rtl:-scale-x-100` for a non-arrow icon). Two deliberate
differences from that transform: a sheet's and the sidebar's `side="left"` is the inline start
(`start-0`, not upstream's physical `left-0`), and the drawer's `swipeDirection` edges and the
tooltip arrow's Base UI `side="left"`/`"right"` stay physical with a `rtl-physical:` comment.
After `shadcn-add.ts <x> --overwrite`, re-apply it (`apps/web/tests/logical-css.test.ts` and
`tests/rtl.test.tsx` fail until you do). The rows below that say only "Logical (RTL) classes"
exist for this alone; the other rows' files carry it too.

**Open Broadcast foundation (D1, `docs/design/2026-11-overhaul`).** Every component also carries
these classes, re-applied after `shadcn-add.ts <x> --overwrite` (`tests/tokens.test.ts` and
`tests/foundation.test.tsx` fail until you do):

- **One focus rule:** `ring-2 ring-ring ring-offset-2 ring-offset-background` (`ring-offset-sidebar`
  in the sidebar) instead of `ring-1`, `ring-3` or `ring-[3px]`, without the `border-ring` recolor;
  resets that drop the ring (`ring-0`) also drop the offset (`ring-offset-0`). The scroll-area
  viewport draws its ring inset (it sits in clipping parents). The slider thumb's ring keys off
  `has-focus-visible:`, because Base UI focuses its nested range input.
- **14 px reading text:** card bodies and descriptions, dialog, sheet, drawer, popover, alert and
  hover-card bodies, field labels, descriptions and errors, empty-state bodies, item titles and
  descriptions, accordion triggers and panels go from `text-xs` to `text-sm`. Tables, tooltips,
  menus, badges and inputs stay `text-xs`.
- **Surfaces:** popups use `shadow-raised` (a shadow in light, none in dark) instead of
  `shadow-md`/`lg`/`xl`; dialog, alert-dialog, sheet and drawer backdrops use `bg-scrim` instead of
  `bg-black/10`. Chart legend and tooltip swatches are square (`rounded-none`, not `rounded-[2px]`).
- **Touch targets:** `Button` `icon` / `icon-lg` grow to 40 / 44 px below md; the slider control
  is at least 24 px tall (44 px on a coarse pointer) and its thumb hit area 44 px on touch.
