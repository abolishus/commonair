# ADR 0014: Audience attestation key, chain and settle delay

- Status: accepted (2026-10-27; the maintainer accepted the recommended answers, see
  [Decisions at acceptance](#decisions-at-acceptance-2026-10-27))
- Date: 2026-10-27 (code checked at `ccf9c17`)

## Context

Signed Audience Attestations (`docs/product/feature-wins.md` §4.8, line 480) give a creator a
statement a sponsor can check without trusting a scraper: per broadcast, verified viewers, what
was excluded and why, and how the stream was delivered, signed by the instance. Feature-wins
leaves the settle delay open and lists this ADR's topics (`feature-wins.md:921`): the worker-only
key with `kid` and rotation history, the threshold hash, the settle constant shared with Creator
Analytics (§4.9), supersede semantics and the advisory-lock chain. The unit is W2b-attestations
(`.claude/briefs/next/W2-feature-wave.md`, batch 5), after W2-rollup-analytics and W0-integrity.

What the code has today:

- **Signing primitives exist, with no new dependency needed.** `packages/tokens` signs Ed25519
  over exact payload bytes with WebCrypto, imports PKCS#8 keys and verifies raw 32-byte public
  keys (`packages/tokens/src/index.ts:28-69`). Relay receipts already ship as base64url payload
  plus signature and are parsed only after the signature verifies (`:121-153`). `sha256Hex` and
  `randomTokenSecret` are there too (`:155`, `:186`). None of it has a key id or key history:
  `PLAYBACK_SIGNING_KEY` is one PKCS#8 value (`packages/config/src/env.ts:349` at HEAD).
- **Secrets reach only the units that read them.** Each Quadlet unit gets only the env keys
  listed for it (`scripts/selfhost/unit-env.ts:5-9`, `:72`; generated `infra/selfhost/env/*.keys`),
  and the installer runs `init-env --merge` to add missing secrets (`scripts/selfhost.sh:710-723`,
  `scripts/init-env.ts:35`).
- **Verdicts settle on a timer.** The scorer revisits an ended session only for `finalizeSeconds`
  after it ends, default 3600 (`packages/integrity/src/jobs.ts:70`, `:190`, `:210`). The slowest
  integrity job runs every 5 minutes with up to 20 minutes per run
  (`services/worker/src/integrity/jobs.ts:42-45`). Past the finalize window, an allowance granted
  later does not bring an excluded ended session back (`packages/integrity/src/jobs.ts:210-212`),
  and the only other writer of `playback_sessions.verdict` is the heartbeat path
  (`services/api/src/routes/playback.ts:270`).
- **W0-integrity has merged** (`be72278`): sessions whose fetches could not be judged carry
  `fetch_unjudged` (`packages/integrity/src/types.ts:37`) and `gateEligible` /
  `GATE_ELIGIBLE` count only verified, judged, scored sessions
  (`packages/integrity/src/score.ts:97`, `packages/integrity/src/jobs.ts:47`).
- **Thresholds are a governance setting**, `integrity.thresholds`
  (`packages/integrity/src/thresholds.ts:15-27`, seeded in `packages/db/src/seed.ts:122`).
  `@commonair/integrity` has no meaningful version (`0.0.0`).
- **`stream.offline` exists** as an event (`packages/contracts/src/events.ts:82`).
  `integrity.channelSummary` is still a stub (`services/api/src/routes/integrity.ts:13`). The
  per-minute rollup (`broadcast_audience_minutes`) is new in W2-rollup-analytics.
- **Several workers may run at once** once ADR 0032 stage 2 adds app droplets, so anything that
  extends a chain must be serialized in the database, not in one process.

## Decisions

### 1. A worker-only Ed25519 key with a `kid` and a published key history

- `INTEGRITY_SIGNING_KEY` (PKCS#8, base64, like `PLAYBACK_SIGNING_KEY`) lives in a new
  `attestationEnv` schema in `packages/config`, in `.env.example`, and is generated by
  `scripts/init-env.ts`. The unit-env list gives it to `commonair-worker` only; the API and web
  never hold it. Self-hosters get it from the installer's existing `init-env --merge`.
- `kid` is the first 16 bytes of SHA-256 over the raw public key, base64url (22 characters).
  It is derived, so it cannot drift from the key.
- `integrity_signing_keys` (new, append-only by trigger apart from setting `retired_at` and
  `compromised_at` once each): `kid`, algorithm, raw public key, `first_used_at`, `retired_at`,
  `compromised_at`. The worker inserts its key's row the first time it signs with it and, in the
  same transaction, retires the previous active key. **Rotation** is replacing the env value and
  restarting the worker; old attestations keep verifying against the published history. While a
  rolling restart is in progress, a worker still holding the retired key has its appends refused
  by the chain trigger (decision 5) until it restarts.
- **Compromise** is an admin action (audited) that sets `compromised_at`. Verifiers reject every
  signature by that `kid`, whatever its date, because a stolen key can backdate. The worker then
  re-issues each affected entry as a `reissue` entry (decision 4) signed by the current key, from
  the figures stored with the original.
- The history is public at `/.well-known/commonair-attestation` on the instance origin
  (`instanceSite()`, AGENTS.md rule 5), served by the API from the table.

**Why.** The worker is the only service that needs to sign, so it is the only one that should be
able to. A derived `kid` plus a public history lets a sponsor verify a two-year-old statement
after several rotations, and lets the operator revoke a key without rewriting anything.

### 2. The statement: exact signed bytes, integers only, a threshold hash

The envelope is `{ payload, signature }`, both base64url, the same shape as relay receipts. The
payload is the JSON of a Zod-parsed statement in schema key order, and its signed bytes are the
statement; verifiers verify the bytes first and parse after. No JSON canonicalization library is
needed and no new dependency is added (`packages/tokens/src/attestation.ts`, written by the
orchestrator in the Wave 2b contract step with vectors in `packages/tokens/vectors.json`).

Fields: schema version `v`, `kind` (`broadcast`, `supersede`, `reissue`), `origin`, `kid`,
`channelId`, `broadcastId`, `seq`, `prevHash`, `supersedes` (an entry hash or null), the period,
`signedAt`, `rulesetVersion`, `thresholdsHash`, and the figures:

- `peakVerifiedConcurrent`, `verifiedViewerSeconds` and `durationSeconds` (the verifier derives
  the average, so the payload carries no floats that TS and Go could print differently);
- `unverifiedViewerSeconds`: pending and `fetch_unjudged` sessions, listed apart from exclusions
  because they are not judged to be bots;
- `excludedViewerSeconds` in total, plus `reasonsCommitment`: SHA-256 over a per-entry random
  salt and the per-reason breakdown;
- delivery bytes by source (origin, relay, CDN).

The breakdown and salt are stored with the row and revealed only to the owner or through an
expiring share link, which the verifier checks against the commitment. So one signed statement
serves both the public totals and the owner-only breakdown.

`thresholdsHash` is SHA-256 over `{ rulesetVersion, thresholds }`, where `thresholds` is the
`integrity.thresholds` setting as parsed at signing time and `rulesetVersion` is a new integer
constant in `packages/integrity`, bumped with any change to what a signal or verdict means. Each
bump gets an entry in a ruleset changelog (new, `docs/governance/integrity-ruleset-changelog.md`).
Statements carry ids and counts only, never user ids or personal data (ADR 0004).

### 3. One settle constant: two hours after the broadcast ends

`AUDIENCE_SETTLE_SECONDS = 7200`, exported from `packages/integrity` beside a new
`DEFAULT_FINALIZE_SECONDS = 3600` that `scoreActiveSessions` uses instead of its inline default.
Both the W2-rollup-analytics job and the attestation job run that long after `stream.offline`;
the attestation job also waits for the broadcast's rollup to exist and reads only that rollup. A
unit test asserts the constant is at least the finalize window plus the slowest integrity job's
interval and run limit (3600 + 300 + 1200 s today).

Publication is separate from signing: owner views and share links show an attestation only after
Creator Analytics' 24-hour display delay (`feature-wins.md` §4.9), so attestations are never a
faster detection oracle than analytics.

**Why.** After the finalize window an ended session's verdict no longer moves on its own, so two
hours covers the last scoring pass and late relay receipts with margin. A longer wait would only
delay the sponsor's proof; the 24-hour delay that protects the thresholds already applies to
publication.

### 4. Supersede, never mutate

`integrity_attestations` is append-only by trigger (the `0001_protections.sql` pattern). Each
broadcast has exactly one `broadcast` entry. When figures change after signing, the worker appends
a `supersede` entry for the same broadcast whose `supersedes` is the hash of the broadcast's
current latest entry; a key compromise appends `reissue` entries the same way. The current
statement for a broadcast is its latest entry; earlier ones still verify and are shown as
superseded.

Two paths trigger a supersede: any code that changes an ended session's verdict after the settle
delay (W2b group appeals, admin decisions) enqueues a re-check for the broadcast, and a daily
reconciler re-derives figures for broadcasts with sessions re-scored after their latest entry. An
entry is appended only if the figures differ. Supersedes stop when the per-minute rollup is
deleted (90 days, §4.9): after that the attestation is final. The scorer does not revisit an
ended session past the finalize window (`packages/integrity/src/jobs.ts:210`), so an overturn only
reaches an attestation if the code that decides it re-scores the session itself.

### 5. A per-channel hash chain, serialized by an advisory lock and checked by a trigger

`entryHash` is SHA-256 over an entry's signed payload bytes; `prevHash` is the channel's previous
entry hash (null for the first). Every append takes `pg_advisory_xact_lock` on
`integrity:attestation:<channelId>` (the `packages/ledger/src/locks.ts:12-14` pattern), reads the
head, signs and inserts in one transaction. The trigger refuses a row whose `seq` is not head + 1,
whose `prevHash` is not the head's hash, whose `kid` is retired or compromised, or a second
`broadcast` entry for one broadcast. Postgres cannot check Ed25519 itself, so signature checks
stay in the worker's own post-sign verification and in tests.

**Why.** The chain makes omission detectable: a verifier given contiguous entries knows nothing
between them was dropped. The lock keeps an offline job and a supersede, or two workers, from
racing to the same head; the trigger enforces the chain at the lowest layer (AGENTS.md rule 9)
even if a caller forgets the lock.

### 6. Window proofs are bundles, not new signatures

A 30-day proof is the channel's contiguous entries from the first in the window through the
current head, plus the key history. The verifier checks every signature, the chain links, and
takes the latest entry per broadcast. The API assembles bundles without the private key, so
nothing but the attestation job ever signs.

### 7. W0-integrity gates attestations

Only `GATE_ELIGIBLE` sessions count as verified. `fetch_unjudged` and pending sessions count as
unverified, never as verified and never as excluded. W0-integrity's code merged in `be72278`; its
PROGRESS.md closure, a red-team pass and the first ruleset changelog entry are still required
before attestations are offered publicly. The verifier page states that excluded traffic is not
proof of wrongdoing (an i18n string) and shows the instance domain prominently.

## Consequences

- The Wave 2b contract step (`feature-wins.md:508`) lands `attestationEnv`, `.env.example`,
  `init-env`, the unit-env key list, both tables and triggers, `packages/tokens/src/attestation.ts`
  with vectors, the settle and finalize constants, and the
  `integrity.attestations.{list, get, share}` contract.
- `packages/sdk` (new in E9) re-exports the verifier from `packages/tokens`; third parties need no
  other code.
- A threshold change through governance during a settle window is attested with the thresholds in
  force at signing. The ruleset changelog and governance history make that traceable.
- W2b-group-appeals must re-score the ended sessions an overturn covers and enqueue the re-check
  (decision 4); today a late allowance does not change an ended session's verdict.
- Our staging droplet gains the key on its next `install --reinstall`; there are no other
  installs to migrate.
- Tests: canonical bytes and tamper vectors; chain trigger tests (wrong `seq`, wrong `prevHash`,
  retired `kid`, a second `broadcast` entry); concurrent offline and supersede appends serialize;
  figures equal session verdicts; `integrity-basic` signed and tamper steps.

## Alternatives considered

- **Sign in the API.** Rejected: the API is internet-facing and has no need for the key.
- **Reuse `PLAYBACK_SIGNING_KEY`.** Rejected: separate purposes need separate keys, and playback
  keys would then need a public history too.
- **JCS or another canonical JSON library.** Rejected: signing exact bytes avoids it and adds no
  dependency.
- **Mutable rows updated on re-score.** Rejected: a sponsor's copy would silently disagree.
- **A signed rollup per window** (feature-wins' wording). Rejected for v1: the worker would have to
  sign on demand for the API, and contiguous signed entries prove the same thing.
- **Settle at the 24-hour display delay.** Rejected: the delay protects publication, not verdicts.

## Decisions at acceptance (2026-10-27)

The maintainer accepted this ADR with the recommended answers:

1. **Key.** Ed25519, worker-only, `kid` derived from the public key, rotation by replacing the env
   value, a public append-only key history, and compromise handled by rejecting the `kid` and
   re-issuing (decision 1).
2. **Format.** Exact signed bytes with integer figures and a threshold hash over the ruleset
   version and the `integrity.thresholds` setting, built on `packages/tokens` primitives with no
   new dependency (decision 2).
3. **Settle constant.** 7200 seconds, shared with Creator Analytics; publication follows
   analytics' 24-hour delay (decision 3).
4. **Supersede and chain.** Append-only supersede entries, a per-channel hash chain under an
   advisory lock, enforced by a trigger (decisions 4 and 5).
5. **Gate.** W0-integrity gates attestations; fetch-unjudged sessions are unverified (decision 7).

Decided within these answers (recorded so reviewers can check them):

- The owner-only reason breakdown is a salted commitment inside the signed statement.
- Window proofs are bundles of signed entries, not a second signature (decision 6).
- Supersedes stop when the per-minute rollup is deleted at 90 days.
