# ADR 0029: Internationalization and community translation

- Status: accepted (2026-10-27; the maintainer accepted the recommended answers, see
  [Decisions at acceptance](#decisions-at-acceptance-2026-10-27))
- Date: 2026-10-27 (code checked at `ccf9c17`)

## Context

Milestone N2 (`.claude/briefs/next/N2-i18n-weblate.md`) makes the web app, the design system and
email render in the viewer's language, with correct plurals, dates and money, and lets the
community translate. Its infrastructure unit (N2-core) runs in batch 3 beside E8 and E9, because
it touches only `apps/web/src/i18n/**`; the remaining N2 units follow.

What the code has today:

- **Every web string goes through `t()`**, which does plain `{name}` replacement with no plurals
  (`apps/web/src/i18n/index.ts:18-22`). The locale is hardcoded: `export const locale = "en"`
  (`:13`). `<html lang>` takes it (`apps/web/src/routes/__root.tsx:56`).
- **Catalogs are typed TypeScript objects** split by area (`apps/web/src/i18n/{coop,money,ops,
  safety,support,p2p,e7-*}.ts`), spread into one `en` object whose keys form `MessageKey`
  (`apps/web/src/i18n/en.ts:17`). `apps/web/tests/i18n.test.ts` checks that used keys exist, bans
  runtime-built keys outside an allowlist (`:41`) and keeps the unit catalogs disjoint.
- **Design-system strings** are `UiMessages` (`packages/ui/src/lib/messages.ts:14`), English only
  (`enMessages`, `:41`). `packages/ui` already has a `LocaleProvider` carrying a locale, a time
  zone and messages (`packages/ui/src/lib/locale.tsx:30`), and the house primitives read it:
  `<MoneyAmount>` and `<ViewerCount>` through `useResolvedLocale` (`:47`), `<RelativeTime>`
  through `useLocale`. The formatters live in `packages/ui/src/lib/format.ts` (`formatMoney`,
  `:40`).
- **Other code formats on its own.** `Intl.NumberFormat` is called directly in
  `packages/ui/src/blocks/coop/tally-table.tsx:88`, `packages/ui/src/blocks/coop/statement.tsx:93`,
  `packages/ui/src/blocks/forms/amount-field.tsx:47`, and `apps/web/src/lib/relays.ts:65`;
  `Intl.DateTimeFormat` in `packages/ui/src/blocks/forms/date-of-birth-field.tsx:47`; and bare
  `toLocaleString()` with no locale (so the browser's default, not the user's) in
  `packages/ui/src/components/chart.tsx:222`, `packages/ui/src/blocks/data/progress-row.tsx:127`
  and `packages/ui/src/blocks/data/breakdown.tsx:170`.
- **Email already resolves locales**: exact tag, then language, then English
  (`resolveCatalog`, `packages/email/src/messages/index.ts:28`), with gaps filled from English
  (`mergeCatalog`, `:15`). Only `en.ts` exists.
- **`users.locale` is `notNull` with default `"en"`** (`packages/db/src/schema/auth.ts:41`), so
  "chose English" and "never chose" look the same. There is no `INSTANCE_DEFAULT_LOCALE` in
  `packages/config/src/env.ts` or `.env.example`.
- **Physical direction is common in class names.** A rough grep for Tailwind classes such as
  `ml-*`, `pr-*`, `left-*`, `border-l-*`, `rounded-r-*` and `text-left` finds roughly 150 to 170
  matches in `apps/web/src` and `packages/ui/src`, depending on the pattern. Nothing checks for
  them.
- There is no `@commonair/i18n` package, though PLAN.md names one.

Nothing has been translated and no instance serves non-English users, so the catalog format can
be replaced outright; there are no translations to migrate.

## Decisions

### 1. ICU MessageFormat through a small in-repo formatter

Messages use ICU MessageFormat for plurals and selects, implemented in `packages/i18n` (new,
N2-core) over `Intl.PluralRules`, with no new dependency. Supported: `{name}` arguments (so every
existing English string stays valid unchanged), `{n, plural, =0 {…} one {…} other {…}}` with `#`,
`{x, select, …}` and `selectordinal`. Number and date skeletons inside messages are not supported:
formatting belongs to the primitives (decision 4). Apostrophes are literal except where ICU uses
them to quote a brace. Why: the subset we need is a few hundred lines with exhaustive unit tests,
while a full ICU library is a dependency to vet and keep current (AGENTS.md rules 2 and 7) for
features we would ban anyway. Weblate's ICU MessageFormat check validates translations against the
same syntax.

### 2. Catalogs are JSON; English is the source of truth

- Catalogs move to `apps/web/src/i18n/locales/<lang>/<namespace>.json`, flat `key: message`
  objects, one namespace per current area file. Why: Weblate edits JSON natively, not TypeScript.
- A generated `.d.ts` (from the English files) keeps `MessageKey` typed, so `t("missing.key")` is
  still a type error. The generator runs in the build and a test fails if it is stale.
- English is the source: keys are added only in `en`, and other locales may lag; a missing
  translation falls back to English per key, as email's `mergeCatalog` does.
- `UiMessages` and email catalogs move to the same JSON format (N2-ui, N2-email).
- JSON cannot carry an SPDX header, so `REUSE.toml` annotates the catalog paths (AGENTS.md rule 1).

### 3. Negotiation, switching and loading

- **Order**: a signed-in user's `users.locale`; else, for a signed-out visitor, the locale they
  picked in the footer switcher (a first-party preference cookie, decided in drafting); else the
  best match from `Accept-Language`; else `INSTANCE_DEFAULT_LOCALE` (new, in
  `packages/config/src/env.ts` and `.env.example`, default `en`). Matching is exact tag, then
  language, then the next candidate, as email resolves today.
- **`users.locale` becomes nullable** with no default: null means "not chosen", so
  `Accept-Language` applies until the user picks. A clean replacement, since no user has chosen.
- **Switcher** in settings (writes `users.locale` through `me.update`) and in the footer (writes
  the cookie, and `users.locale` when signed in).
- **The cookie is a Preferences cookie** under the published cookie policy
  (`packages/db/src/legal/cookies.md:35-40`), which keeps that category off until the visitor
  allows it. A signed-out visitor who has not allowed preferences still gets the language they
  picked, for the current tab only; it is not stored.
- **Loading**: English is bundled; other locales are fetched by dynamic import of their JSON when
  negotiated, before first render on the server and on switch in the client. `<html lang>` and
  `dir` follow the active locale.

### 4. Only the house primitives format

`<RelativeTime>`, `<MoneyAmount>` and `<ViewerCount>` are the only components that format times,
money and viewer counts, taking the active locale from `LocaleProvider`. Other numbers and dates
(percentages, plain counts, month names, amount input) go through the formatter functions in
`packages/ui/src/lib/format.ts`, also with the active locale passed in. Direct `Intl.*`
construction outside `format.ts` and argument-less `toLocaleString()` are banned by a check that
N2-ui adds, and the call sites listed in Context move to `format.ts`.

### 5. Right-to-left from the start: logical properties, checked

Layout uses logical CSS properties and their Tailwind forms (`ms-*`, `pe-*`, `start-*`,
`border-s-*`, `text-start`, …), never physical ones, except where direction is truly physical (a
progress bar's fill, a media timeline). A check fails on physical-direction classes and
properties outside an allowlist; Oxlint has no rule for this, so it is a repository check that
N2-core adds beside `apps/web/tests/i18n.test.ts`. N2 converts the existing matches. Arabic
(`ar`) is the next locale after the first, to prove RTL end to end.

### 6. The first second locale is Spanish; `en-XA` ships regardless

The first real locale is **Spanish (`es`)**, as one catalog for all regions until translators ask
for a regional split. Why: after English it is one of the largest streaming audiences, and it is
left-to-right, so N2 tests plurals and string length without also taking on RTL in the same
milestone. The pseudo-locale **`en-XA`** (accented, about 35% longer, bracketed) ships in every
build for testing: `e2e-basic` runs under it, so any literal that bypasses `t()` shows up
unaccented.

### 7. Translation runs on Hosted Weblate's libre plan

- **Where.** The project uses Hosted Weblate's gratis plan for libre projects, run by the Weblate
  project, instead of a server we host. This replaces the N2 plan's self-hosted Weblate. Why: it
  is the same FOSS software (GPL-3.0-or-later); it is free for libre projects; translations still
  reach us only as pull requests; and AGENTS.md rule 3 is about the platform's runtime, which an
  operator runs, while the translation workflow is the project's and is not part of any instance.
  Hosting our own would mean patching, backups and an account system for no product gain.
- **Flow.** Weblate commits to its own branch and opens PRs from the Weblate bot. The component's
  commit template adds a `Signed-off-by` for the translator, and the component's contributor
  agreement shows the DCO text, which each translator accepts before saving. PRs pass the same
  gate as any other; the ICU check and the key-type generator catch broken messages.
- **Licensing.** UI catalogs are AGPL-3.0-or-later like the code they ship in; docs strings are
  CC-BY-SA-4.0. Both are declared on the Weblate components and in `REUSE.toml`.
- **Fallback.** If the libre plan is refused or withdrawn, we self-host Weblate for the project
  (not for instances), as the N2 plan first proposed.

## Consequences

- N2-core owns the format change, the `packages/i18n` formatter, the generator, negotiation, lazy
  loading, the pseudo-locale and the logical-property check. E8 and E9 strings land in the English
  catalog in whatever format is current when they merge; N2-core converts what it finds.
- The contract step makes `users.locale` nullable and adds `INSTANCE_DEFAULT_LOCALE` to
  `packages/config/src/env.ts` and `.env.example` together (a test enforces the sync).
- Code that reads `users.locale` to pick an email's language (for example
  `services/api/src/routes/me.ts:87`, `services/api/src/lib/leaks.ts:66`,
  `services/worker/src/moderation/sor-deliver.ts`) must treat null as `INSTANCE_DEFAULT_LOCALE`,
  not English, so the contract step updates every reader with the column.
- The footer switcher sets a preference cookie, which `packages/db/src/legal/cookies.md` must list
  under Preferences, with theme and player settings.
- N2-weblate no longer writes `infra/weblate/**`; it writes the Weblate component configuration
  notes and `docs/maintainers/translations.md`, and the maintainer applies for the libre plan and
  installs the Weblate GitHub integration.
- Adding a language is adding a directory of JSON files and a locale entry; no code change.
- Locale-aware formatting outside the primitives becomes a reviewed exception, not a habit.

## Alternatives considered

- **A full ICU library** (FormatJS and similar). Rejected for now: a dependency for features we
  would not allow in messages. Revisit if the subset grows.
- **Keep TypeScript catalogs** and convert for Weblate. Rejected: a round trip that loses
  comments and ordering, and Weblate's checks run on its own format.
- **`users.locale` default `en`** with Accept-Language only for signed-out visitors. Rejected:
  signed-in users would never get their browser's language without a manual switch.
- **Arabic first.** Rejected for the first locale: RTL plus plurals plus length in one milestone
  is too many new failure modes at once. It is next.
- **Self-hosted Weblate from the start.** Rejected for operating cost with no product gain; kept
  as the fallback.
- **A proprietary translation service.** Rejected: not FOSS, and contributors would need accounts
  on a closed platform.

## Decisions at acceptance (2026-10-27)

The maintainer accepted the recommended answers:

1. **Message format.** ICU MessageFormat plurals and selects through a small in-repo formatter
   over `Intl.PluralRules`, no new dependency, keeping `{name}` placeholders.
2. **Storage.** JSON catalogs under `apps/web/src/i18n/locales/<lang>/<namespace>.json` with a
   generated `.d.ts` keeping `MessageKey` typed; English is the source of truth.
3. **Negotiation.** `users.locale`, else `Accept-Language`, else `INSTANCE_DEFAULT_LOCALE`; a
   switcher in settings and the footer; non-English catalogs lazy-loaded.
4. **Formatting.** Only `<RelativeTime>`, `<MoneyAmount>` and `<ViewerCount>` format, taking the
   active locale.
5. **RTL.** Logical CSS properties checked by a lint rule; Arabic is the next locale after the
   first, to prove RTL.
6. **Second locale.** Spanish (`es`): a very large streaming audience after English, and
   left-to-right, so plurals and length are tested without RTL in the same milestone. `en-XA`
   ships regardless.
7. **Weblate.** Hosted Weblate's free libre-project plan, not a self-hosted server (this changes
   the N2 plan). Same FOSS software run by the Weblate project, free for libre projects,
   translations still arrive as DCO-signed PRs from the Weblate bot; AGENTS.md rule 3 concerns
   the platform's runtime, not the translation workflow; running our own means patching and
   backups for no product gain. Fallback: self-host if the libre plan is refused. Licensing: AGPL
   for UI catalogs, CC-BY-SA-4.0 for docs strings.

Decided in drafting within these answers (recorded so reviewers can check them): `users.locale`
becomes nullable so Accept-Language can apply to signed-in users who never chose; a signed-out
visitor's footer choice is kept in a first-party preference cookie; formatting outside the three
primitives goes through `packages/ui/src/lib/format.ts` (answer 4 read as "only the primitives
format times, money and viewer counts; everything else formats through `format.ts`"); the RTL
check is a repository check rather than an Oxlint rule; `es` is one catalog for all regions.

Settled in review (2026-10-27): the locale cookie is in the cookie policy's optional Preferences
category, so it is set only with that consent; without it, a signed-out visitor's choice lasts
for the tab.
