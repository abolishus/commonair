# E4c web ↔ harness contract (trust & safety)

Milestone E4c: automated moderation and the human workflows around it ([ADR 0006](../decisions/0006-automated-moderation.md),
licenses in [ADR 0008](../decisions/0008-trust-safety-licenses.md)). A live frame that matches
a known-illegal hash list ends the stream, suspends the account, hides its VODs and clips, puts
the evidence on legal hold and drafts an NCMEC report, with no human in the loop. A classifier
score blurs and queues (T1) or labels and gates 18+ (T2), and a human always decides what
happens next. Reports, the mod queue, appeals and the public NCII takedown form with its 48-hour
clock complete the slice. This file extends [e1](e1-selectors.md), [e2](e2-selectors.md),
[e3](e3-selectors.md) and [e4b](e4b-selectors.md), and everything in those still holds.

Changing anything here is a contract change: update this file, `packages/moderation`,
`services/media`, `services/worker`, `services/api`, `apps/web` and the `trust-safety` scenario
together. Tests select elements by `data-testid`, never by visible text.

## Safety rules (absolute; a reviewer marks any breach HIGH)

- **No real harmful material, ever.** Nobody obtains, generates, downloads, describes or handles
  real CSAM, NCII or other illegal material, or searches for it. Tests and the harness use only
  **synthetic geometric images** (`packages/moderation/fixtures/`, generated by code in the repo)
  whose PDQ hashes go into a fixture list, plus the `ScriptedClassifier`. The real default
  classifier runs in tests only on benign images (the PDQ reference photos, generated patterns),
  as a smoke test. No industry hash list is downloaded or embedded: NCMEC, Tech Coalition,
  StopNCII and hosted classifiers are optional adapters configured by operators.
- **Logs carry ids, categories, tiers, scores, distances and list/model versions only.** Never
  frames, image bytes, hashes of non-matching content, URLs or keys of evidence, emails, IPs or
  free text.
- **The pipeline cannot be switched off.** No env var, governance setting or code path disables
  sampling, matching or classification. Missing or invalid configuration makes the service
  refuse to start (fail closed). Only providers can be swapped. An empty hash list is a valid
  list (the local block list is always loaded).
- **No ban from a classifier score alone.** T1 and T2 blur, delist, label and queue; only a human
  suspends or bans on them. T0 (a hash match on a known-illegal list) is the only automatic
  suspension.
- **One transaction per automated action**, with the `audit_log` row (actor type `system`,
  `details` = ids, tier, category, score/distance, `provider`, `providerVersion`) and the
  `events` row. Every automated action is reversible by a moderator, except the T0 legal hold and
  the T0 removal of public media copies (they exist afterwards only as sealed evidence).
- **T0 material is shown only to the `legal` role**, through `moderation.evidence`, decrypted in
  the API, never cached, every view audited. It never appears in the ordinary mod queue, in
  thumbnails, in logs, in events or in any other UI.
- **Personal data stays out of append-only columns** (AGENTS.md). The one deliberate exception is
  the sealed NCMEC draft snapshot (ADR 0006 Q3): the legal duty outranks deletion, and it is
  encrypted.

## Tiers and thresholds

| Tier | Trigger                                                                                                               | Constants and settings                                                                                                                                                                              |
| ---- | --------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T0   | PDQ distance ≤ `PDQ_MATCH_DISTANCE` (31) to an entry on the CSAM or NCII list, frame quality ≥ `PDQ_MIN_QUALITY` (50) | Code constants in `@commonair/moderation` (`MODERATION_CONSTANTS`), never settings                                                                                                                  |
| T1   | a category score ≥ its T1 threshold                                                                                   | governance `moderation.thresholds.t1.<category>`. Ranges (trigger-checked): `sexual` 0.85–0.995 (default 0.97), others 0.5–0.995 (defaults `graphic_violence` 0.9, `weapons` 0.95, `self_harm` 0.9) |
| T2   | `sexual` ≥ T2 threshold on a channel not labelled mature (and below T1)                                               | governance `moderation.thresholds.t2.sexual`, 0.5–0.95, default 0.80, and strictly below `t1.sexual`                                                                                                |
| T3   | everything else                                                                                                       | nothing stored per frame. Counters only (`moderation_frames_total{tier}`, score histograms per category)                                                                                            |

Sampling interval: `min(MODERATION_SAMPLE_SECONDS env (2–60, default 10), moderation.thresholds.sampleSeconds (5–60, default 10))`.
A category the provider does not score is **not scored** (never 0) and never fires. The default
classifier scores only `sexual`. The settings trigger rejects out-of-range or missing values,
and the worker validates the setting with the same ranges and falls back to the defaults if it
is somehow invalid (fail closed).

## Scenario `trust-safety`

Runs against the stack with the fixture hash list mounted (`MODERATION_HASHLIST_CSAM` and
`MODERATION_HASHLIST_NCII` pointing at `packages/moderation/fixtures/*.pdq`, synthetic patterns
only), `MODERATION_CLASSIFIER=scripted`, `MODERATION_SAMPLE_SECONDS=2` and
`MODERATION_TEST_HOOKS=true`. **Test hooks** (off by default; the API and worker log a warning
at every start while on, and `/healthz` reports it; never set on a public instance) allow the
`scripted` classifier and two internal routes, both behind `INTERNAL_API_SECRET`:
`PUT /internal/moderation/script` (`{ channelId, scores }` → `KEYS.moderationScript(channelId)`
in Valkey, read by the scripted classifier) and `POST /internal/moderation/ncii-tick`
(`{ asOf }` → runs the NCII clock job once at that time). Without test hooks, `scripted` is
refused at startup and both routes are `404`. `--set via=api` drives everything through the API
(no browser); the default also checks the web flows. Accounts are created fresh; `legal` (×2),
`moderator` and `admin` roles come from the role CLI.

1. **T0 live.** Streamer A publishes the synthetic fixture pattern (`packages/moderation/fixtures/t0-pattern.png`
   looped by ffmpeg). Within `2 × MODERATION_SAMPLE_SECONDS` + 5 s slack: the broadcast has
   ended, A's channel is suspended (`channels.get.suspended`) and a new publish with A's key is
   refused.
   Through the API as legal user L1: one `legal-case` with `data-list="csam"`, evidence present,
   a hold with reason `csam_match`, an NCMEC draft with status `draft`; A's VODs and clips list
   empty (owner and public view). The audit log for the case has `moderation.t0.match`.
2. **Evidence survives deletion.** Admin calls `admin.expediteDeletion` for A (creates the
   deletion request if there is none, due now; audited). The worker completes it. A's users row
   is pseudonymized; `moderation.evidence` for the case's evidence still returns data to L1, the
   hold and draft still exist, and `account_deletions.retained` lists the held tables. Deleting
   the evidence row, the hold or the draft as the app role (harness DB helper) fails.
3. **T0 dismissal needs two.** On a second synthetic T0 case (streamer B, NCII fixture list): L1 dismisses →
   `dismissal_pending`; L1 dismisses again → refused; L2 dismisses → `dismissed`, B unsuspended,
   the hold still present.
4. **T2 label and appeal.** Streamer C live, scripted `sexual = 0.85`: within two intervals C's
   channel is `mature`, `/$channel` shows `mature-gate` to a signed-out viewer and a playback
   token is refused with `mature_gate`; C sees `moderation-label-notice`, appeals; a moderator
   overturns on `/admin/appeals`; the channel is no longer mature and the gate is gone.
5. **T1 blur, queue, clear.** Streamer D live, scripted `sexual = 0.99`: within two intervals D's
   stream is gone from the directory, `/$channel` shows `stream-restricted`, and a `modq-item`
   with `data-tier="t1"` exists with a blurred `modq-frame` (`data-revealed="false"`). The moderator
   clears it; the stream is listed again; `modq-history` shows `moderation.t1.restrict` (actor
   `system`) and `moderation.case.clear` (actor `moderator`).
6. **Upload rejected.** Streamer E requests an avatar upload URL, PUTs the synthetic fixture image,
   and `channels.commitUpload` fails with `upload_rejected`; the avatar is unchanged; nothing
   under `channels/<E>/avatar/` exists; a T0 case exists for E.
7. **NCII clock.** A takedown request through `/takedown` (or `ncii.submit` with `via=api`) for
   one of F's clips returns a receipt with `deadlineAt` = receipt time + 48 h (±5 s). The worker's
   harness calls `POST /internal/moderation/ncii-tick` with `asOf` = receipt + 48 h + 1 min: the clip is hidden (`removed_reason = "ncii_deadline"`) and the audit log shows
   `ncii.auto_hide`. A second request for another clip decided `removed` within the window
   removes it and adds its hashes to the local block list; re-uploading that clip's first frame
   as a panel image is rejected.

Steps are individually selectable (`--set steps=1,2,5`). Every step asserts the logs contain no
frame data, URLs or emails (the harness greps the services' captured logs for the fixture's
bytes in base64 and for the test accounts' emails).
