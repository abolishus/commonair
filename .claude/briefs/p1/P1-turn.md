## Why

WebRTC between viewers needs ICE servers. The amendment rules out public STUN (a third party
would learn every P2P viewer's address; AGENTS.md non-negotiables 3 and 4): the instance's own
coturn is the only default. STUN always runs; the TURN relay is **off by default** because a
relayed peer's bytes cross the droplet twice, so it saves no egress (amendment decision 2), but an
operator can turn it on. When it is on, credentials are short-lived TURN REST credentials minted
by the API for sessions that hold a P2P grant, and the relay must never reach the instance's
private network. Self-host parity: what our instance runs, `selfhost.sh` offers every operator.

## Build

1. **coturn configuration** (`infra/coturn/`), rendered from env at start (no secret in the image
   or in git):
   - Always: `listening-port=$TURN_PORT`, `fingerprint`, `no-cli`, `no-tlsv1`, `no-tlsv1_1`,
     `no-multicast-peers`, `stale-nonce`, a `realm` (`PUBLIC_HOSTNAME`, or a fixed dev name),
     `external-ip` when `TURN_EXTERNAL_IP` is set.
   - Relay **off** unless the operator turned it on: with it off, coturn answers STUN binding
     requests only (find the coturn option set that refuses allocations, e.g. `stun-only`).
     With it on: `use-auth-secret`, `static-auth-secret=$TURN_SHARED_SECRET`, `min-port`/`max-port`
     from the relay range, `user-quota`, `total-quota`, `max-bps` (state numbers and why), UDP
     relay only.
   - **Never relay into private space**: a `denied-peer-ip` for every range in
     `services/api/src/lib/netrange.ts` `BLOCKED_V4`/`BLOCKED_V6` (:12-42). That list is wider
     than private space and includes the documentation, NAT64, Teredo and 6to4 ranges. Add the
     IPv4-mapped forms (`::ffff:0:0/96` of each IPv4 range). Generate the lines from that file in
     the test so they cannot drift.
     With host networking this keeps Valkey, Postgres, Garage (127.0.0.1:3900) and Grafana
     (127.0.0.1:3030) out of reach. A harness-only override for private peers, if a TURN test
     needs one, is off by default and never in Quadlet.
   - Logging: no client address reaches Loki. coturn logs sessions with addresses by default:
     turn that off and say how an operator debugs instead. Prometheus metrics, if the image has
     them, on an internal port only.
   - TURN over TLS (`turns:`) is a follow-up: say what it would take.
2. **Compose** `coturn` service: the pinned image, the rendered config, `TURN_PORT` udp (and tcp
   if you keep it) bound to `BIND_ADDRESS`, the relay range only when the relay is on (a compose
   profile, e.g. `turn-relay`, is fine), a healthcheck, in the default profile.
3. **Quadlet** `commonair-coturn.container`, styled like the other units (header comment,
   `RunInit=true`, `EnvironmentFile=` from its key list with the `render-env.sh` `ExecStartPre=`,
   restart and health as in `commonair-tracker.container`), plus what step 1's networking
   decision needs.
4. **`selfhost.sh`**: `configure_env` writes `P2P_STUN_URLS=stun:$host:3478` and
   `TURN_EXTERNAL_IP` (from `--public-ip` / the address MediaMTX uses; that can be an
   `IPv4,IPv6` list, so take its first IPv4 entry); `backfill_env` does the same
   on upgrade without touching set values (`TURN_SHARED_SECRET` comes from init-env in
   `write_env`). `check_ports` and `firewall_hints` include `3478/udp`. `--turn-relay` (off by
   default, persisted across `upgrade`) writes `P2P_TURN_URLS=turn:$host:3478?transport=udp`,
   enables the relay in coturn, and adds the relay range to the firewall hints with a warning
   that DigitalOcean's cloud firewall needs it opened by hand. `cmd_status` says whether coturn
   runs and whether the relay is on, never the secret.
5. **API credentials** (`services/api/src/p2p/turn.ts` + `routes/p2p.ts`), TURN REST scheme:
   `username = "<expiry epoch s>:<opaque id>"`, `credential = base64(HMAC-SHA1(TURN_SHARED_SECRET,
   username))`, expiry = now + `TURN_CREDENTIAL_TTL_SECONDS`. The opaque id is **not** the raw
   session id: it is a truncated HMAC of the session id under a subkey of `TURN_SHARED_SECRET`
   (amendment decision 2, because coturn can log usernames). Pick the subkey label and the
   truncation length (at least 16 bytes, base64url) and document both in `p2p/turn.ts`. Handler: verify the
   token for `sessionId`, `CONFLICT` for an ended session, `PRECONDITION_FAILED` reason `p2p`
   without `KEYS.p2pGrant(sid)`, then one entry with the `stun:` URLs (no credentials) and, only
   when `P2P_TURN_URLS` is set, one with the `turn:` URLs and credentials. `expiresAt` is `null`
   when there is no TURN entry. Both lists empty → `{ iceServers: [], expiresAt: null }`.
   `P2P_TURN_URLS` set without `TURN_SHARED_SECRET` cannot start (the contract step's
   refinement). Still fail closed in the handler (`INTERNAL_SERVER_ERROR`, one warning log, no
   secret in it) in case deps are built by hand in tests.
6. **Docs.** `docs/self-hosting/p2p.md`: what P2P delivery is, what coturn does, why no public
   STUN, why the relay is off by default and when to turn it on (its egress cost), ports and
   firewalls (host and DigitalOcean), the private-range denial, and how to check it works
   (`turnutils_stunclient` / `turnutils_uclient` from the image, with credentials from the API).
   Also `P2P_DEFAULT` (amendment decision 3): P2P is opt-in by default (`off`); an operator may set
   `on` only with a lawful basis for showing viewers' IP addresses to other viewers (in the EU,
   counsel has not reviewed one for the reference instance), and even then phones, metered
   connections and data mode stay off. `configuration.md`: the keys.
