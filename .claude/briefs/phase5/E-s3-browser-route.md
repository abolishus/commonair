# Unit E: browser uploads and export downloads on a self-hosted instance (ADR 0024)

You are implementing unit E of the Phase 5 follow-up for CommonAir (repo:

## The problem

Presigned avatar/banner/panel uploads (`channels.uploadUrl`, `PUT S3_BUCKET_MEDIA/incoming/…`)
and data-export downloads (`GET S3_BUCKET_EXPORTS/<key>`, from the API and from the export mail)
point at `http://garage:3900` on a self-hosted instance, because `selfhost.sh` never sets
`S3_PUBLIC_ENDPOINT` and Caddy has no route to Garage. ADR 0024 decides the fix: the
path-style bucket URL on the main host, unstripped, with a narrow Caddy allowlist.

## Contracts you must honor (read-only for you)

- ADR 0024 exactly. Caddy forwards to `garage:3900`, with path and `Host` unchanged, only:
  - `PUT /{$S3_BUCKET_MEDIA}/incoming/*` with an `X-Amz-Signature` query parameter, request body
    capped at 10 MB (the `sizeBytes` max in `packages/contracts/src/api/router.ts`; leave a little
    headroom only if Caddy counts differently, and say so);
  - `GET`/`HEAD /{$S3_BUCKET_EXPORTS}/*` with an `X-Amz-Signature` query parameter.
    Everything else under those paths falls through to the web app. The handlers sit before the
    web fallback and must not disturb the existing routes, the CSP or the security headers.
    Decide whether `encode` should apply to these responses (exports are already zip) and
    whether any response header Caddy adds would break a signed `GET` (it must not).
- `@commonair/storage` (`packages/storage/src/index.ts`) builds path-style URLs on
  `S3_PUBLIC_ENDPOINT`; do not change it.
- `selfhost.sh` stays POSIX sh and shellcheck-clean (CI: `lint-workflows`), keeps its CLI
  (`install|upgrade|backup|status`) and its existing `env_set`/`env_default` helpers.
- The e2e's CLI contract (`bun scripts/selfhost/e2e.ts [--distro debian|fedora] [--keep]`) and
  Podman 4.9 compatibility (CI runs it on ubuntu-24.04).
- Do not edit `scripts/verify.ts`, `package.json`, `bun.lock`, `infra/containers/**`,
  `REUSE.toml`. Report needed changes as contract requests.

## Build

1. Caddy: the two matchers and handlers above, using `{$S3_BUCKET_MEDIA}` and
   `{$S3_BUCKET_EXPORTS}` (give Caddy those variables wherever it runs: Quadlet unit, compose
   `tls` profile; defaults `commonair-media` / `commonair-exports` as in `.env.example`).
2. `selfhost.sh install`: `env_set S3_PUBLIC_ENDPOINT "https://$_host"` next to
   `MEDIA_PUBLIC_URL`. `upgrade`: if the installed env file has no `S3_PUBLIC_ENDPOINT`, set it
   from `PUBLIC_HOSTNAME`; never overwrite an operator's value (an external S3 store).
3. e2e (inside the test host, through Caddy and the internal CA with `curl --cacert`):
   - presign with the API's own storage config, e.g. `podman exec commonair-api bun -e …`
     importing `@commonair/storage` (`storageFromEnv(process.env)`); find how the service image
     lays out the workspace so the import resolves;
   - a presigned `PUT` of a small object to `S3_BUCKET_MEDIA/incoming/…` returns 2xx and the
     object exists afterwards (`HEAD` with the service key from inside the network, or a
     presigned `GET` through the internal endpoint);
   - a presigned `GET` of an object put into `S3_BUCKET_EXPORTS` returns its exact bytes and the
     `content-disposition` the presign asked for;
   - refusals, each must not be 2xx: an unsigned `PUT` to the incoming path; a presigned-looking
     `GET` of `S3_BUCKET_MEDIA/incoming/…`; a `PUT` outside `incoming/`; a `GET` of another
     bucket (`S3_BUCKET_EVIDENCE`, `S3_BUCKET_BACKUPS`); a bucket listing
     (`GET /<exports>?list-type=2`); a `DELETE`.
   - run the same checks again after the upgrade to the second release (the backfill itself
     is covered by a unit test below, since v1 already writes the variable).
4. Docs: what an operator sees (nothing to configure), and what to set for an external S3
   store (its endpoint, CORS, CSP `connect-src`), per ADR 0024 "Consequences".
