## Build

1. **`docs/self-hosting/`** (CC-BY-SA-4.0 SPDX header in every file). Write for an operator
   who has never seen the repo.
   - `README.md`: what you get, the 10-minute path, a map of the pages.
   - `requirements.md`:
     - Debian 13 / Fedora 42+;
     - Podman 5;
     - CPU, RAM and disk (from ADR 0010 and the E6 load test as documented in PROGRESS, or
       marked as an estimate);
     - DNS;
     - ports, including UDP 8189 and 443/udp;
     - an SMTP relay;
     - optional off-host S3.
   - `install.md`:
     - prepare the server;
     - download `selfhost.sh` from a release, and verify it against `SHA256SUMS` and with
       cosign before running it (no `curl | sh`);
     - one `install` command;
     - what it checks and writes;
     - the first admin account (find out how one is made; check the API and harness);
     - first-stream smoke test (OBS RTMP and WHIP).
   - `configuration.md`: a reference of every env variable, grouped by schema, with default,
     required/optional, and a description from the JSDoc. Generated by
     `scripts/config-reference.ts` between marker comments.
     `scripts/tests/config-reference.test.ts` fails when the committed doc is out of date,
     when a variable in `ALL_ENV_SCHEMAS` or `.env.example` is missing from it, or when it
     lists one that does not exist.
   - `tls.md`: ACME (DNS first, rate limits, `ACME_CA` staging), `TLS_MODE=internal` for
     LAN/testing and trusting its root, and the IRC certificate sync.
   - `upgrades.md`:
     - `selfhost.sh upgrade`, and exactly what it does in order;
     - rollback, and when it cannot help (schema);
     - the additive-migration rule from ADR 0023 §9;
     - pinning a version;
     - mirrors.
   - `backups.md`: WAL-G daily base backup, off-host S3 (Hetzner Object Storage or a second
     Garage), `selfhost.sh backup`, restore with `commonair-restore`, and the restore drill
     ("an untested backup does not count").
   - `scaling.md`: ADR 0010 §3 order (separate DB/Valkey, more origin/media, member relays and
     P2P before any CDN), and what to watch (port utilization).
   - `relays.md`: running a member relay from the released binaries or image, verifying the
     binary, registering with a relay token.
   - `verifying.md`:
     - `cosign verify` for images;
     - `cosign verify-attestation --type cyclonedx` and the SLSA type for SBOM/provenance;
     - `cosign verify-blob --bundle` for binaries and `SHA256SUMS`;
     - the exact identity and issuer flags from ADR 0023;
     - reading an SBOM.
   - `mirroring.md`: run Zot or CNCF Distribution, `cosign copy` a release, `selfhost.sh
     --registry`.
   - `troubleshooting.md`: `selfhost.sh status`; `journalctl --user -u …`; unhealthy units;
     ACME failures; WHIP behind NAT (`MTX_WEBRTCADDITIONALHOSTS`, UDP 8189); linger
     missing; ports below 1024; Postgres; disk full; abuse reports (link
     `docs/operators/trust-safety.md`).
2. **`docs/maintainers/releasing.md`**:
   - prerequisites: branch protection on `ci-ok`, ghcr package visibility public, arm64
     runners;
   - cutting `v0.1.0-rc.1`: green main, tag, push, watch;
   - a dry run on a fork or with `workflow_dispatch`;
   - verifying the published release yourself;
   - promoting rc to stable;
   - yanking a bad release;
   - the changelog;
   - what to do when signing or an arch build fails.
3. **README.md**:
   - refresh the contributor quickstart: clone, `bun install`, `bun scripts/init-env.ts`,
     `bun scripts/infra.ts test`, `bun run verify --quick`, `podman compose up`, the harness;
     check each command exists;
   - make the "Self-hosting" section link to `docs/self-hosting/` (it already links there)
     and show the install command for the latest release.
4. **`docs/deploy/hetzner.md` and `infra/README.md`**:
   - replace the manual steps with `selfhost.sh` where it now does them;
   - keep the Hetzner-specific parts (Robot, installimage, firewall, Object Storage);
   - update "Gaps before go-live" to what is still true;
   - `infra/README.md`'s Quadlet section describes rendered units, release directories and
