## Build

1. **PDQ port** (`src/pdq.ts`, plus internal files such as `src/pdq/*.ts`): a faithful TypeScript
   port of ThreatExchange `pdq/` at tag **`hma-v1.1.7`** (github.com/facebook/ThreatExchange,
   BSD-3-Clause): luminance input, Jarosz filter downsample to 64×64, 2D DCT to 16×16, median
   threshold to 256 bits, quality metric; hex output in the reference bit order. Each ported file
   carries `SPDX-FileCopyrightText: Meta Platforms, Inc. and affiliates` plus ours, and
   `SPDX-License-Identifier: BSD-3-Clause` (ADR 0008). `hammingDistance` on hex with popcount.
   Do not name Meta or Facebook in product copy (clause 3).
2. **Reference vectors.** Copy the benign reference photos and expected hashes from
   `pdq/data/reg-test-input` (and its expected-output file) at that tag into
   `packages/moderation/tests/vectors/`. Those are the only files you fetch from outside the repo
   besides the model. Tests: exact hash and quality on raw luma decoded the reference way (if the
   reference decodes RGB→luma itself, port that conversion and feed it decoded RGB); through the
   ffmpeg path (`decodeImage`) a Hamming distance ≤ 8 and the same quality band, because decoders
   differ. Record in the test file how each vector was decoded.
3. **Hash lists** (`src/hashlist.ts`): file format and `version` as documented in the file;
   `parseHashList` throws `HashListParseError(line)` on any bad line; `loadHashListFile` (empty
   path → empty list, version `empty:0`); `staticHashList`; `createHashMatcher` (nearest across
   lists, `null` below quality 50 or beyond distance 31, CSAM before NCII on a tie; a linear scan
   is fine up to ~100k entries, measure and document); `watchHashListFiles` (SIGHUP and `fs.watch`,
   debounce, keep the last good list on a parse error, call `onError`; return a stop function).
   Never log hashes or file contents.
4. **Classifiers.** `scriptedClassifier(readScript)` per its doc comment. `createOnnxClassifier`
   in `src/onnx.ts` (the only file that imports `onnxruntime-node`): read the file, check its
   sha256 against `MODEL.sha256` (mismatch or missing file → throw; no fallback), create a CPU
   session, preprocess RGB 384×384 as the model's `preprocessor_config.json` says at the pinned
   revision (ViT: rescale 1/255, normalize mean 0.5 / std 0.5, NCHW float32), softmax, map the
   NSFW label (read the label order from the revision's `config.json` `id2label`, record it in a
   comment with the revision) to `{ sexual }` only. `provider = MODEL.provider`,
   `providerVersion = "<revision 8 chars>:<sha256 12 chars>"`, `scored = ["sexual"]`. Bun must load
   the N-API addon: if it cannot, stop and report (the fallback is a Node sidecar, a user decision).
5. **ffmpeg helpers** (`src/frames.ts`): `decodeImage` (stdin → `-frames:v 1`, scale with
   `-vf scale=W:H:flags=area` to luma 512² `gray` and RGB 384² `rgb24`, raw output; refuse inputs
   ffmpeg cannot decode; time limit; never write temp files with image data outside a private temp
   dir that you remove), `sampleVideoFrames` (`fps=1/everySeconds`, both sizes per frame, t = 0
   included, async iterator that kills ffmpeg on early return), `encodeImage` (PNG and JPEG via
   ffmpeg). Use `Bun.spawn`, no shell.
6. **Synthetic fixtures** (`fixtures/`): a generator script (`fixtures/generate.ts`, run with
   `bun`) that draws deterministic geometric patterns as raw pixels and encodes them with
   `encodeImage`: `t0-pattern.png` (the CSAM-list fixture: large high-contrast shapes, robust to
   H.264 and rescaling), `t0-ncii-pattern.png` (a second, different pattern for the NCII list),
   and three benign patterns that must **not** match either list. It writes `fixtures/csam.pdq`
   and `fixtures/ncii.pdq` (one hash each, with a `# synthetic fixture` comment). Commit the
   generated files and test that regenerating reproduces them. Name and comment them as synthetic
   test patterns only.
7. **Robustness tests** that the scenario relies on: `t0-pattern.png` encoded to H.264 by ffmpeg
   (as the harness will loop it), then sampled with `sampleVideoFrames`, matches `csam.pdq` with
   distance ≤ 31 and quality ≥ 50 on every sampled frame; the benign patterns and a black frame do
   not match (the black frame has quality < 50); the NCII pattern matches only `ncii.pdq`.
8. README: what each module does, the fixture policy, how to add an operator list.
