**SAFETY RULES (repeated; absolute):** never obtain, generate, download, describe or handle real
CSAM, NCII or other illegal material, and never search for it. Tests use only the synthetic
fixtures in `packages/moderation/fixtures/`, generated bytes and the scripted classifier; the
ONNX model runs only on benign images. Never download or embed industry hash lists. Logs carry
ids, categories, tiers, scores, distances and versions only. No env, setting or code path
disables classification; bad config refuses to start. **No ban from a classifier score alone.**
Every automated action writes `audit_log` (actor `system`) and `events` in the same transaction
and records the provider version.

This unit owns **every T0 transaction**, holds eligibility, evidence storage and audit, the NCII
clock and account deletion: it gets a second, security-focused review. Losing evidence or skipping
a T0 action is HIGH.

## Build

1. **Startup.** `MODERATION_CLASSIFIER=onnx` → `createOnnxClassifier({ modelPath:
   MODERATION_CLASSIFIER_MODEL || DEFAULT_MODEL_PATH })`, failure → exit. `scripted` requires
   test hooks (the env schema enforces it) and reads `KEYS.moderationScript(channelId)`. While
   `MODERATION_TEST_HOOKS` is on, log a warning at every start and report it in `/healthz`.
   Import `EVIDENCE_PUBLIC_KEY`; build a second S3 client with `S3_EVIDENCE_*` for
   `S3_BUCKET_EVIDENCE`. Missing any → exit.
2. **`scan`**: load the RGB frame (missing → counter `moderation_frames_expired_total`, no action),
   classify, `tierFor` with `parseThresholds` (an invalid setting → defaults and an alert log), and
   act only on T1/T2. T3: counters and score histograms only. For T1/T2 encode the frame as JPEG
   and store it at `reviewFrameKey(caseId, flagId)` in the media bucket.
   - **T1** one transaction per spec (flag, case or reuse the open case for the broadcast, priority
     `T1_PRIORITY`, `sla_due_at` = now + 15 min, `broadcasts.restricted_at`/`restricted_case_id`,
     audit `moderation.t1.restrict`, events `moderation.flagged` + `moderation.restriction`).
   - **T2** one transaction per spec (flag, `content_labels`, `channels.mature = true`, case
     `labelled`, owner `notifications` row type `moderation` with ids only, audit
     `moderation.t2.label`, events `channel.update` + `moderation.flagged`). Already mature → nothing.
3. **`t0`** (one transaction, retried with backoff until it lands, `fatal` log with ids if it
   cannot): `moderation_flags` (t0), `moderation_cases` (t0, `open`, `list_category`), `legal_holds`
   (`csam_match`/`ncii_match`), one `evidence_objects` row per sealed evidence item (inline),
   `users.banned` + `ban_reason = "t0_hash_match"`, `channels.suspended_at` + `suspended_reason`,
   the broadcast ended (`stream.offline`), every VOD and clip of the broadcast (live) or the subject
   VOD/clip set `deleted` with `removed_reason = "t0_hash_match"`, audit `moderation.t0.match`,
   events `moderation.flagged` and `legal.hold.placed`, and for the CSAM list the `ncmec_reports`
   draft with the sealed `NcmecSnapshot` (account email, username, display name, IP hashes and raw
   IPs still held for the user: sessions and auth log) and `ncmec.draft.created`. Idempotent: a
   second job for the same subject finds the open case and does nothing new. Publish the
   `UserControlMessage` `suspended` after commit. Then enqueue `t0-media`.
4. **`t0-media`** (idempotent, retried, alert on repeated failure): for each VOD segment, playlist,
   clip file and stored thumbnail of the broadcast, read it from the media bucket, seal it, put it
   under `evidence/<caseId>/<evidenceId>` in the evidence bucket, insert its `evidence_objects`
   manifest row (`storage = bucket`, plaintext sha256, kind `vod_object`/`clip_object`/`thumbnail`),
   then delete the public copy. Seal per object (HLS segments are small); never hold a whole VOD in
   memory. Never delete a public copy whose evidence copy is not verified (re-read + sha256).
   Storage key: `evidence/<caseId>/<evidenceId>.<sha256 of the sealed bytes>` (see item 8).
5. **`t0-escalated`**: the full T0 actions for a human-escalated case confirmed by `legal`
   (suspend, hide, hold `csam_confirmed`, evidence from the case's flags/subject, draft if none).
6. **`ncii-clock`** (every minute and on demand with `asOf`): 24 h → `escalated_24_at` and notify
   moderators and `legal` again; 36 h → `escalated_36_at`, notify `legal` and admins; 48 h undecided
   → `auto_hidden_at`, each resolved item hidden (VOD/clip `deleted` with `removed_reason =
   "ncii_deadline"`, upload references cleared and objects moved to a private prefix, live ended),
   audit `ncii.auto_hide` (actor `system`), event `ncii.request.decided` (`auto_hidden`). A run more
   than `NCII_CLOCK_LAPSE_ALERT_MINUTES` after the previous one raises an alert. Under a run lock.
7. **`ncii-hash`**: for a `removed` request, PDQ every sample interval of each removed VOD/clip and
   each removed upload image (quality ≥ 50) into `local_hash_list` (`ncii`, source `ncii_request`),
   then delete the objects. Idempotent.
8. **Schedules**: `evidence-audit` (daily: re-read every bucket object and compare the sha256 of
   its sealed bytes with the one recorded at write time; the worker cannot open sealed bytes, so
   the storage key is `evidence/<caseId>/<evidenceId>.<sha256 of the sealed bytes>` (decided; the
   manifest's `sha256` column stays the plaintext digest, which the legal view can re-check);
   inline objects: count and `octet_length`
   per row, which the append-only trigger already protects; record `evidence_audit_runs`; a missing
   or changed object → `incidents` row + `fatal` log with ids), `ncmec-unfiled` (alert after 24 h, `incidents` row after 72 h, once each),
   `hold-eligibility` (set `eligible_for_release_at` = `filed_at` + 365 days when due),
   `frame-retention` (delete review frames 30 days after their case closed), `incoming-cleanup`.
9. **Account deletion** (`QUEUES.deletions`, every few minutes): due `account_deletions` →
   delete or pseudonymize per ADR 0004 (sessions, tokens, keys, follows, chat history, …; read the
   schema and existing code for every table that references users), pseudonymize the `users` row
   (`pseudonymized_at`, `deleted_at`, username/email/name replaced), and leave held tables untouched
   (`legal_holds`, `evidence_objects`, `moderation_flags`, `moderation_cases`, `ncmec_reports`);
   `retained` = `[{ table, reason: "legal_hold", rows }]` for each held table with rows. Publish
   `UserControlMessage` `deleted`. One transaction per user; idempotent.
10. README sections and metrics for every job.
