## SAFETY RULES (absolute; a reviewer marks any breach HIGH)

- **Never obtain, generate, download, describe or handle real CSAM, NCII or any other illegal
  material, and never search for it** (not on the web, not in datasets, not in model outputs).
- Tests and the harness use **only synthetic geometric images** generated by code in
  `packages/moderation/fixtures/` (checkerboards, gradients, shapes, noise with a fixed seed)
  whose PDQ hashes go into the fixture `.pdq` lists, plus the **scripted classifier**. The real
  ONNX classifier runs in tests **only on benign images** (the PDQ reference photos and generated
  patterns), as a smoke test.
- **Never download or embed industry hash lists** (NCMEC, Tech Coalition, StopNCII, IWF, PhotoDNA).
  Operators configure those as optional adapters.
- **Logs carry ids, categories, tiers, scores, distances and list/model versions only.** Never
  frames, image bytes, hashes of non-matching content, URLs or object keys of evidence, emails,
  IPs, names or free text.
- **The pipeline cannot be disabled** by config, governance or code path. Missing or invalid
  configuration makes the service refuse to start (fail closed). Only providers are swappable.
- **No ban ever comes from a classifier score alone.** T1/T2 blur, delist, label and queue. Only
  T0 (a hash-list match) suspends automatically.
- **Every automated action writes its `audit_log` row (actor `system`, `details` = ids, tier,
  category, score/distance, `provider`, `providerVersion`) and its `events` row in the same
  transaction**, and records the model or list version that fired.
- **T0 material is visible only to the `legal` role**, through `moderation.evidence`: never in
  the ordinary mod queue, thumbnails, logs, events, notifications or any other UI or API.
- **Personal data never goes into append-only columns** (audit `details`, flags, evidence
  metadata, events). The sealed NCMEC snapshot is the one deliberate exception (ADR 0006 Q3).

**What counts as HIGH in review** (in addition to the above): losing or mutating evidence;
skipping or partially applying a T0 action (stream left on air, account not suspended, media left
public, no hold, no draft for CSAM); showing T0 material outside `legal`; any way to switch the
pipeline off or make sampling rarer than the spec allows; a T0 dismissal by one reviewer; an NCII
deadline that can be missed silently; an automated action without its audit row and event in the
same transaction; a log line with personal data or evidence locations; a race that double-applies
or loses a decision (state changes are compare-and-set or row-locked).

**Database-first.** Triggers in migration 0016 already enforce holds, append-only evidence and
flags, two-reviewer dismissal, the NCII deadline and the mature-label lock. Application checks
are in addition, never instead. Your integration tests should prove the application path works
**and** that the database refuses the bypass where your unit touches those tables. Never weaken a
trigger; if one blocks a legitimate flow, stop and report a contract request.

**Web rules** (unit E, and anyone touching UI). AGENTS.md "Design rules (web)" and "House
primitives" are hard rules, enforced by `apps/web/tests/source-policy.test.ts`. Build pages only
from `packages/ui` layouts, blocks and components; `packages/ui/stories/pages/TrustSafety.stories.tsx`
shows the intended composition. A missing composition is a contract request, never page-local
styling. Test ids may reach the DOM through composition props (list them in
`apps/web/tests/composition-ids.ts`, prove them in `selectors-render.test.tsx`). Every e1–e4b id
stays intact.

**Process.** You work in your own git worktree: run `git merge main --no-edit` first, then
`bun install` if `node_modules` is missing. Do not edit contracts, db schema/migrations, config,
root `package.json`, `bun.lock`, scripts, `compose.yaml` or root lint config: report a contract
request instead (the head agent applies them). No new npm dependencies unless your brief says
so. Never add anything to `trustedDependencies`. Units B, C and D depend on unit A's
implementations: code against the signatures now; once A is merged to `main`, `git merge main
--no-edit` again before your final checks.

## Done means (every brief)

- **Targeted checks only.** The user runs the gate (`bun run verify`), image rebuilds, harness
  scenarios against the live stack, dev servers, Storybook and every browser/visual check. You do
  not. Run: your packages' `bun run test` and `bun run test:int` (the data services are already up
  at the `.env.example` defaults; never run `podman compose`, `scripts/infra.ts` or
  `infra`'s `test:int`, which starts its own compose project), `bunx tsc -p <pkg> --noEmit`,
  `vp lint --deny-warnings <changed paths>`, `vp fmt <changed paths>`, `vp build` for `apps/web`,
  `build-storybook` for `packages/ui`. Never run several packages' `test:int` at the same time.
  Note: in zsh, pass several paths as separate words (`vp lint a.ts b.ts`), not one quoted string.
- No files outside your ownership list changed (`git status`).
- Commit in your worktree with `git commit -s` (Conventional Commits) and explicit paths, never
  `git commit -a`; message ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`,
  once your targeted checks pass.
- Final message: what you built, test counts per package, branch + commit sha, **contract
  requests** (exact changes needed in files you do not own), anything left undone, and the exact
  commands the user should run live to exercise your work.

## Review (the head agent runs this; know what you will be held to)

An independent reviewer reads your diff against this file, the spec and AGENTS.md **before**
merge. Any HIGH is fixed and gets a focused re-review. Units B (media), C (worker) and D (API) also
get a **second, security-focused reviewer** (T0 path, holds, deletion, evidence storage, NCII
clock, authorization, log hygiene) even when the first finds no HIGH.
