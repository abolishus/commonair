**SAFETY RULES (repeated; absolute):** never obtain, generate, download, describe or handle real
CSAM, NCII or other illegal material, and never search for it. Tests use only the synthetic
fixtures in `packages/moderation/fixtures/` and generated bytes. Never download or embed industry
hash lists. Logs carry ids, categories, tiers, scores, distances and versions only (no emails,
names, IPs, URLs, keys or free text; NCII requester data never reaches a log or an audit
`details`). No ban from a classifier score alone. Every automated action writes `audit_log` and
`events` in the same transaction. **T0 material is returned only to the `legal` role, only by
`moderation.evidence`, decrypted in the API, never cached (`cache-control: no-store`), every view
audited.**

This unit is on the T0, evidence and NCII paths: it gets a second, security-focused review.
Authorization mistakes (a moderator reaching T0 data, a non-legal user reaching evidence, the
uploader learning that a list matched) are HIGH.

## Build

1. **Startup.** Load the env (fail closed). Import `EVIDENCE_PUBLIC_KEY` (sealing uploads and
   snapshots) and `EVIDENCE_PRIVATE_KEY` (opening, only in the legal handlers' module). Load the
   operator lists and the local list for upload matching (`@commonair/moderation` matcher,
   reloaded like media). Test hooks on → a warning at every start and `/healthz` reports it.
2. **Uploads.** `uploadUrl` presigns to `incoming/channels/<id>/<purpose>/<uuid>.<ext>`.
   `commitUpload` (owner) validates the key belongs to the channel and purpose, fetches it,
   `decodeImage` (first frame for GIFs; audio purposes skip image checks but are still size- and
   type-checked), PDQ match → seal the image, enqueue `t0` for subject `upload` with the uploader,
   delete the incoming object, fail `UNPROCESSABLE_CONTENT` `upload_rejected`. Classifier: run the
   configured classifier (the ONNX one is heavy; if you decide the API should not load it, enqueue
   a synchronous worker check instead and report the choice) → ≥ T1 creates a T1 case (no
   restriction) and rejects; ≥ T2 `sexual` rejects without a case. Same response for every
   rejection. Otherwise copy to `channels/<id>/<purpose>/<uuid>.<ext>` and return `{ key, url }`.
   Everything that accepts an image key (`channels.update` avatar/banner, `setPanels`, emotes,
   alerts) must refuse `incoming/` keys and keys that were never committed.
3. **Mod queue** (`safety-staff`): `queue`/`case` never return T0 (`NOT_FOUND` for a T0 id),
   `frame` returns the stored T1/T2 JPEG (never T0), `notScored` from the configured provider,
   `history` from `audit_log`. `review` per the spec (CAS on `open`, audit `moderation.case.<decision>`
   with the moderator as actor, event `moderation.case.resolved`, restriction lift with
   `moderation.restriction` false, `escalate_legal` → tier `t0`, origin `human`).
4. **Legal** (`legal` only): `t0Queue`, `t0Confirm` (status `confirmed`, evidence PDQs with quality
   ≥ 50 into `local_hash_list`, draft if none for CSAM, enqueue `t0-escalated` for human-origin
   cases, audit `moderation.t0.confirm`), `t0Dismiss` (two different legal users who are not the
   subject; second one unbans and unsuspends only if the reason is still `t0_hash_match`, withdraws
   an unfiled draft; the hold stays; `mediaRestored: false`), `evidence` (inline only, opened with
   the private key, `no-store`, audit `evidence.view`; bucket objects → their metadata only),
   `ncmecReports`, `ncmecReport` (decrypted snapshot, audit `ncmec.view`), `ncmecFile` (sets
   `filed_at` on the report and the hold, audit `ncmec.filed`), `holds`, `admin.legalHold`
   (reason `law_enforcement`/`litigation`, audit, `legal.hold.placed`).
5. **Reports** (`safety.report/queue/resolve/suspend/auditLog/modLog`): one open report per
   reporter and subject; `minor_safety` and `ncii` get priority `URGENT_REPORT_PRIORITY` and notify
   every `legal` user; reports become report-derived cases where the spec says so; suspension with
   audit and `UserControlMessage`.
6. **NCII**: `submit` (public, ALTCHA, `write` limit; `received_at`/`deadline_at` from the DB;
   resolve each URL to a subject on this instance where possible; audit `ncii.received` without
   requester data; event `ncii.request.received`; notify moderators and `legal`), `queue`,
   `decide` (`removed`: unpublish every resolved subject in the transaction and enqueue `ncii-hash`;
   `rejected` with a reason; CAS on undecided; audit `ncii.decide`; event `ncii.request.decided`).
7. **Labels and appeals**: `me.labels`; appeals on `content_label` (overturn → label removed,
   `channels.mature = false` if no other active label, case `cleared`, audit
   `moderation.label.remove`, `channel.update`) and `moderation_case`.
8. **Restriction and gate**: restricted broadcasts are absent from directory lists, search, the
   front page and random; `channels.get` returns `live.restricted = "under_review"` and
   `thumbnailUrl: null`; VODs/clips of a restricted broadcast are not listed or playable until the
   case closes as cleared. Playback of a mature broadcast → `MATURE_GATE` unless signed in, adult
   and confirmed.
9. **Account deletion**: `me.deletion.request` (scheduled now + 30 days), `cancel`, `get`
   (`retained` from the row); `admin.expediteDeletion` (admin, reason, audited, creates the request
   if none, due now). The worker completes them (unit C).
