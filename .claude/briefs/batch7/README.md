## Shared rules

- **How units start.** Each unit is told "read and implement `<brief>`" and gets its own git worktree. Branches: `w3/rooms`, `w3/portability`, `w3/giveaways`,
  `w3/jury`, `w3/surge-raids`, `w3/predictions`, `n3/import`, `n4/api`, `n4/delivery`, `n4/web`,
  `w3/dvr-relay`, `b7/followups`. Commit with `git commit -s`, Conventional Commits and the `Co-Authored-By` trailer. Copy `.env` into the
  worktree root (`bun scripts/init-env.ts --merge` there if keys are missing) and run `bun install` if needed.
- **Pipeline per unit:** implement, then an independent reviewer (the diff against AGENTS.md, this README, the brief
  and the ADRs it cites; per-unit focus in `HANDOFF.md`), then the implementer's fix pass.
- **Targeted checks only** (`.claude/briefs/_done-means.md` and each brief):
  - package tests and `test:int` (one `test:int` at a time), `tsc`;
  - `vp lint --deny-warnings` and `vp fmt` on every changed file;
  - `vp build` for web units, `reuse lint`, `go test ./...` and `go vet ./...` for `relay/`;
  - for catalog changes, `cd apps/web && bun run i18n:check && bun --bun vp test run tests/i18n.test.ts`.
- **Never run locally:** `bun run verify`, `verify:full`, `podman compose`, `scripts/infra.ts`, an image build or a harness scenario. **CI on `main` is the gate.** The user runs every browser and visual check.
- **Contract requests** (exact diffs) go to the orchestrator. No unit creates a namespace, edits
  `keys/index.gen.ts`, an English catalog it does not own, a migration or a shared contract file.
- **Data rules (AGENTS.md):**
  - Money is integer cents; points are integers.
  - Every write with a side effect writes its outbox event in the same transaction.
  - Every moderator, admin, integrity, jury and federation-admin action writes `audit_log`.
  - No personal data in append-only columns: room messages, remote handles, entrant ids and juror votes' free text never go there.
- **Batch 6 lessons** (HANDOFF.md) bind every unit:
  - raw-SQL timestamps go through `harness/src/w2/sql-time.ts`, and Bun.SQL arrays through `sql.array`;
  - read env through `loadEnv`, never `schema.parse(process.env)`;
  - harness expectations follow the seeded defaults;
  - `vp fmt` every touched file; write `es` with every new English key.
